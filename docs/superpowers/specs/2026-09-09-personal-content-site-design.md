# 个人内容网站设计规格

## 1. 目标与定位

建立一个持续更新的个人内容网站，面向对 AI 应用技术和交易系统感兴趣的读者。网站以专业、克制的编辑型阅读体验建立个人品牌，核心不是聚合资讯，而是沉淀个人的学习、实践和复盘。

首期只支持内容发布和阅读，不包含社区、付费或在线编辑后台。

## 2. 内容与信息架构

### 首页

- 最新发布：混排长文章与短复盘卡片。
- AI 应用技术分享精选。
- 交易系统分享精选。
- 关于我入口。

### AI 应用技术分享

- 个人学习与总结：大模型基础与原理、AI 工具与工作流、AI Coding 实践。
- 案例分享：网站或应用实战、AI 内容生产、问题复盘与踩坑。

### 交易系统分享

- 交易理念与规则。
- 风控与仓位管理。
- 交易系统复盘。

### 其他页面

- 关于页：个人背景、网站说明、联系方式。
- 交易风险声明：明确内容仅为个人研究、系统分享与复盘记录，不构成投资建议。

## 3. 视觉与体验

采用编辑型内容站视觉方向：低干扰、专业、长期耐看。

- 首页以一篇精选长文建立内容价值，再展示按时间排序的最新内容。
- 顶部导航清晰分流到“AI 应用技术分享”和“交易系统分享”。
- 长文章优先保障字体、段落、代码块、目录和移动端阅读体验。
- 短卡片在首页及分类页直接展示完整摘要或短复盘，降低更新门槛。
- 不用夸张的动效或金融行情式视觉，避免削弱知识内容的可信度。

## 4. 首版功能范围

### 包含

- 首页、频道页、栏目页、标签页、长文章页、短复盘卡片、关于页和风险声明页。
- Markdown 内容渲染。
- 标签、发布日期、阅读时长、文章目录、代码高亮、上一篇/下一篇。
- 响应式布局。
- 发布前内容字段校验与构建检查。

### 不包含

- 用户注册、登录、评论、点赞。
- 站内搜索。
- 在线网页编辑后台。
- 付费订阅、支付、会员系统。
- 实时行情、荐股或交易信号。

## 5. 内容模型

内容以仓库中的 Markdown 文件管理。每篇内容均有统一元数据：

- 标题、发布日期、摘要、封面图（可选）、主频道、子栏目、标签。
- 内容类型：`article`（长文章）或 `note`（短卡片）。
- 是否精选、是否置顶。
- 交易内容的风险声明开关（默认开启）。

构建时校验必填字段与栏目合法性。文章只能选择一个主频道与一个子栏目；标签可多选，用于横向关联。

## 6. 技术与部署架构

- 项目采用 `frontend/` 与 `backend/` 两个顶级目录。`frontend/` 使用 Astro 构建静态网站，并使用其 Markdown 内容集合能力管理文章；`backend/` 保存部署脚本、Nginx 配置模板和自动发布所需文件。
- 不使用数据库；文章和图片作为仓库内容随 Git 版本管理。
- 云服务器安装 Nginx，托管构建产物；网站通过 HTTPS 域名访问。
- 提交到主分支后，自动执行构建、校验并安全同步构建产物到服务器。
- 服务器仅保存静态网页和部署所需的受限凭据，不保存 Markdown 原稿或仓库访问密钥。

发布数据流：

```text
本地 Markdown 写作 → Git 提交 → frontend 自动字段校验与构建 → backend 发布脚本同步静态文件到服务器 → Nginx 对外提供 HTTPS 访问
```

部署失败时，线上保持前一个成功版本；发布记录应保留失败原因，便于定位问题。

## 7. 验收标准

- 首页能展示精选内容和最新内容，并清楚区分两个频道。
- 读者能从频道进入子栏目、文章和短卡片。
- 新增一篇合法 Markdown 内容后，构建出的页面包含正确标题、分类、标签、日期和正文。
- 必填字段缺失或栏目不合法时，构建失败且不发布。
- 在桌面与手机宽度下，首页、频道页、文章页和风险声明页均可正常阅读。
- 云服务器部署后，HTTPS、刷新访问和文章链接均正常；失败发布不会覆盖线上旧版本。

## 8. 后续演进

当 Markdown + Git 发布流程成为瓶颈时，再接入轻量 CMS 或编辑后台。内容字段、页面结构与 Nginx 静态部署保持不变，降低迁移成本。`backend/` 当前不提供 API、数据库、认证或业务逻辑。
